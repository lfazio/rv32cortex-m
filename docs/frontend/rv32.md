# The RV32 frontend

`include/rv32/` and `src/frontend/rv32/` — RISC-V RV32, the frontend the
project was built for, and the one with reference models to disagree
with: the official architecture suite, the Berkeley suite and Sail.

| Area | State |
|---|---|
| RV32IMAFDC + Zicsr, Zicntr, Zifencei, Zicbom, Zicboz, Zba, Zbb, Zbc, Zbs, Zcf, Zcd, Zcb | implemented |
| Zicond, Zihintpause, Zihintntl, Zicbop, Zihpm, Sscofpmf, Zacas, Zalasr, Zawrs | implemented — [below](#the-small-extensions) |
| Zfhmin, Svinval | implemented — [below](#profiles) |
| RISC-V profiles | **RVI20U32**; the RVA profiles are 64-bit only — [below](#profiles) |
| M-mode traps, interrupts, CLINT timer, APLIC | implemented |
| **U-mode and S-mode** | implemented, including `MPRV` and trap delegation |
| **PMP** | 16 entries, TOR/NA4/NAPOT |
| **Sv32** | two-level paging, 4 MiB megapages, 32-entry TLB; Svade (A/D checked, not written) |
| **Sdtrig** | mcontrol triggers on execute/load/store |
| **F** and **D** | implemented on SoftFloat, for both backends; the JIT lowers the exact single-precision arithmetic to the host FPU |
| **V** | not implemented |

It boots Linux 6.12 through OpenSBI, with Sv32 paging and userspace in
U-mode, to a login prompt on a virtio root filesystem — see the README.

Suite results and how to reproduce them: [../validation.md](../validation.md).

Enabling `F` forces `Zcf` on RV32, and `D` forces `Zcd`: `C@2.0` is
defined to include the compressed FP load/stores, and UDB rejects the
config without them.

## Guest memory map

Defined once — the shared part in
[`include/emu/emu_memmap.h`](../../include/emu/emu_memmap.h), the RISC-V
devices in [`include/rv32/rv_memmap.h`](../../include/rv32/rv_memmap.h) —
and the same on every platform, so a guest binary runs unchanged on the
host runner and on the target.

| Base | Size | Kind | Contents |
|---|---|---|---|
| `0x0200_0000` | 48 KiB | virtual | CLINT — `msip`, `mtimecmp`, `mtime` (SiFive layout) |
| `0x1000_0000` | 256 B | virtual | Console UART — NS16550 subset |
| `0x2000_0000` | image | ROM | Guest image, executed in place from the host's flash |
| `0x3000_0000` | | virtual | framebuffer control and pixels, keyboard, mouse — where a platform has them |
| `0x4000_0000` | 512 MiB | **passthrough** | ARM peripherals, identity-mapped |
| `0x8000_0000` | what is left | RAM | `.data`, `.bss` and the stack: 232 KiB on the F746 with the JIT at its default, 309 without |

Who backs each region, and why the image costs no RAM, is in
[../memory.md](../memory.md).

## Passthrough policy

The peripheral window is not wide open. A per-region permission table
(`g_periph_map` in each board's `platform.c`, for instance
[`src/platform/stm32f446/platform.c`](../../src/platform/stm32f446/platform.c))
withholds only what would take the emulator down with the guest:

| Region | Access | Why |
|---|---|---|
| `PWR` | read-only | dropping over-drive at 180 MHz stalls the core |
| `RCC` `CR`/`PLLCFGR`/`CFGR`/`CIR` | read-only | reconfiguring the PLL kills the clock the emulator runs on |
| `FLASH` controller | read-only | it can erase this firmware underneath us |
| everything else | read/write | |

Note what is deliberately **not** withheld: the rest of RCC, including
`AHB1ENR` / `APB1ENR` / `APB2ENR`. A guest driver has to be able to ungate its
own peripheral's clock — denying that would push every driver back into the
firmware and defeat the design.

A reserved address inside the window is not a harmless near miss: the
AHB signals an error, which is a HardFault in the *emulator*, not a
fault delivered to the guest.

## Floating point

There is **one** FP implementation. SoftFloat is the FP unit — not an
option, and a missing checkout is a configure error rather than a
fallback. Everything that rounds, classifies or reports a flag goes to
`rv_hart_fp`, from the interpreter and from both JIT backends — with one
bounded exception: the JIT lowers the five operations IEEE 754 specifies
exactly (add, subtract, multiply, divide, square root, single precision,
round-to-nearest) to the host FPU, with the NaN canonicalisation and the
flag hand-over written out. Policy and measurements are in
[../jit/floating-point.md](../jit/floating-point.md).

Things about it that are easy to get wrong:

- **NaN-boxing is a change to F, not an addition beside it.** D widens
  the register file to 64 bits, and from then on a single carries
  all-ones in its upper half or is read as the canonical NaN. Every F
  operation is affected, and the failures do not point at the
  instruction that got it wrong: the *next* reader sees a NaN. Route
  every read and write through one pair of accessors.
- **Boxing is per instruction.** `FLW` and `FMV.W.X` *write* boxed;
  `FSW` and `FMV.X.W` *read raw*, because a store moves bits and putting
  it through the unboxing read would write a canonical NaN to memory.
- **`-ffp-contract=fast` silently breaks an error-free transformation,
  and only on hosts that have an FMA.** An earlier FP unit recovered a
  product's rounding error with 2Product/2Sum so that an FMA rounded
  once, which is exact only if `a * b - p` is evaluated as written. GCC's
  default fuses precisely that expression wherever an FMA exists, so the
  error computed as zero and the result rounded twice. The linked F746
  firmware had **eleven** `VFMA`/`VFNMS` inside `rv_hart_fp`; x86-64 has
  no FMA in this build and was correct, which is why no host suite saw
  it. That arithmetic went with the move to SoftFloat, and the flag has
  now gone too: `rv_fpu.c` compiles to identical object code with and
  without it, for the M7 as well as the host.

  It generalises: **any algorithm that depends on an intermediate being
  exactly the rounded value needs contraction off**, and nothing warns
  you. It was caught only by `tests/guest/fptest.c` running the *same
  guest binary* on the host and the board and disagreeing — a
  differential check across implementations, not against an expectation.

## The small extensions

Nine that are each a few lines of semantics, and where the work was
everything around the semantics. The banner names all of them, with
the two from [Profiles](#profiles):

```
RV32IMAFDCB_zicbom_zicbop_zicboz_zicntr_zicond_zicsr_zifencei_zihintntl_zihintpause_zihpm_zacas_zalasr_zawrs_zfhmin_zcb_zbc_sscofpmf_svinval
```

| | here | reference |
|---|---|---|
| **Zicond** | one line in the interpreter. The translator lowers it as compare, negate, AND -- branch-free on both hosts, and not `EMU_IR_SELECT`, which reads guest flags RISC-V does not have and which Thumb-2 declines | arch-test, 2 tests |
| **Zihintpause**, **Zihintntl**, **Zicbop** | no code at all, and no gate: `pause` is a FENCE, `ntl.*` are ADDs into x0 and `prefetch.*` are ORIs into x0, which the base ISA already executes. What makes them *implemented* is that they are claimed -- named by the disassembler, declared to UDB and Sail, and tested for the absence of a trap. For a prefetch that includes one aimed at an address with nothing behind it: it is a hint, not an access | arch-test, 1 + 4 + 4 + 6 tests |
| **Zihpm** | `mhpmcounter3`-`31`, all 29, each a real 64-bit counter with its event selector, its inhibit bit and its unprivileged shadow | arch-test, 2 tests |
| **Sscofpmf** | per counter, an overflow bit and an inhibit for each privilege mode in `mhpmevent3h`-`31h`; `scountovf`; the overflow interrupt, 13 | Sail and Spike, by probe; no suite |
| **Zacas** | `amocas.w`, and `amocas.d` over even-odd register pairs | arch-test, 2 tests |
| **Zalasr** | load-acquire and store-release, through the same `rv_hart_atomic` every other atomic goes through | Spike, by probe; no suite and no Sail |
| **Zawrs** | `wrs.nto` parks the hart as WFI does while a reservation is live; `wrs.sto` returns at once | Sail and Spike, by probe; no suite |

**What the counters count is traps, and only traps.** The architecture
leaves the events to the platform. An emulator can count for nothing
what it already stops to deal with -- every exception, every interrupt,
or one cause exactly -- and a count of loads or taken branches would be a
test on the path every instruction takes, paid by every guest that never
programs a counter. So: `1` any exception, `2` any interrupt,
`0x100 | c` and `0x200 | c` one cause, and the selector is WARL -- a
value not on that list reads back as zero, which is how a guest asks
what exists. A guest that programs nothing pays one load and one
not-taken branch per *trap*.

**Sscofpmf is what a profiler needs from those counters**: a counter
that wraps sets its OF bit and pends interrupt 13, LCOFI -- but only if
OF was clear, so a handler that leaves OF set is saying "seen, do not
interrupt me again". MINH, SINH and UINH stop a counter for one mode,
and the mode an event belongs to is the one the trap was taken *from*:
an `ebreak` in S that M handles is S's event, not M's. `scountovf`
gathers the OF bits for S-mode, showing only the counters `mcounteren`
grants; LCOFI is delegatable, then pending and clearable through
`sip`, and ranks below every standard interrupt.

There is no suite, and the model counts no events, so the reference is
in two halves. `tests/arch-test/probes/sscofpmf.S` asks Sail 0.13.1
eleven questions about everything *around* an overflow -- which bits of
`mhpmevent3h` exist, what `mideleg` and `sie` accept, what S-mode sees
in `scountovf` and `sip` and whether it may clear it, and which of STI
and LCOFI is taken first -- and the emulator gives the same eleven
answers. The counting is `isatest`'s `sscof-*` checks: the wrap, the
interrupt taken once and not again while OF is set, each inhibit, and
S-mode's view, on both backends; eight mutants of the implementation
each fail them. Declaring it to UDB also has the suite's start-up clear
`mhpmevent3h`-`31h` before every test, which is 510 runs of a write to
each.

**The state is at the end of `rv_hart_t`, and was not at first.** It is
352 bytes, and 468 with Sscofpmf's. Beside the other counters, where it reads best, it moved the
FP registers, the state word and the fetch guard by that much; where the
emulator's own data and code land has been measured at 10% on the F746
with nothing else changed. Cold state goes where it displaces nothing.

**An atomic never completes misaligned**, whatever `RV32_MISALIGNED`
says about ordinary loads and stores: splitting it is the thing it
exists to rule out. Zalasr's ordering bit is mandatory -- there is no
load-release and no store-acquire -- and those encodings, and a non-zero
unused register field, are illegal rather than executed as their
neighbour.

**`wrs.nto` is a WFI with a precondition, because with one hart that is
what it is.** Nothing else can write the reserved word, so the only
event that ends the wait is an interrupt -- and taking one drops the
reservation, which is the invalidation the guest was waiting for. With
nothing reserved it completes at once. Below M with `mstatus.TW` set it
is illegal *only when it would wait*. Sail 0.13.1 was asked directly --
`tests/arch-test/probes/zawrs.S`, seven cases, read from its trace --
and agrees on six, including all three below M. The seventh is M-mode
with a reservation and no interrupt enabled: this parks, the model
carries on, both are permitted, and no self-checking test can hold the
case without one of the two hanging.

**Spike reads the TW rule the other way**, and so does UDB's formal
description: below M with TW set, `wrs.nto` traps even with nothing
reserved, before anything could wait. The prose ties the trap to a
`wrs.nto` that "does not complete within an implementation-specific
bounded time limit", and a bound of zero makes that reading legal too.
Two models, two permitted readings; this core is on Sail's side.

**Zalasr's only reference is Spike.** UDB knows it; Sail does not --
not 0.13.1, which the suite is pinned to, nor 0.15 or the nightly of
2026-10-12 -- and riscv-arch-test has no suite. Spike has it, and
`tests/arch-test/probes/zalasr.S` asks it thirteen questions: twelve
agree. The thirteenth is a store-release to the reserved word between
an LR and its SC. This core fails the SC -- any store to the reserved
word ends the reservation, its own included, one rule for every store
path -- and Spike keeps the reservation and the SC succeeds. The A
extension requires the failure only for another hart's store and lets
an SC fail for any other reason, so both are allowed, and isatest's
`sw.rl-ends-reservation` tests this core's choice rather than the
architecture.

How the probes run, and where the models come from:
[../validation.md](../validation.md#probes-and-the-reference-models).

**Zicbom and Zicboz were wrong below M for as long as they existed**,
and are listed here because the same piece of work found it. `menvcfg`
and `senvcfg` say what S-mode and U-mode may do with the cache-block
operations -- CBZE for cbo.zero, CBCFE for clean and flush, the two-bit
CBIE for inval -- and both registers were stored, read back and
consulted by nothing. The maintenance operations also took the guest's
virtual address straight to the bus and skipped PMP. All of it is
checked now; see [../validation.md](../validation.md) for how it was
found.

None of them is in `RV_GUEST_MARCH`, and that has been measured rather
than assumed. Only Zicond changes what the compiler emits, and built
with it:

| guest | `czero` sites | executed | retired | under the JIT |
|---|---|---|---|---|
| CoreMark | 4 | 15 of 518,236 | +2 | nothing to see |
| Dhrystone, crypto | 0 | | | |
| mmiobench | 1 | 8 | −8 | nothing to see |
| `bench` | 1, in the CRC loop | 32,768 | −2.6% | **20% slower** |

`bench` was slower because the compiler pairs `czero` with `bexti`, and
the translator declined `bexti`: one instruction interpreted per turn of
the loop, block entries up 2.9×. That was never about Zicond, and the
translator lowers `bexti` now -- see
[the bit-manipulation extensions under the JIT](#the-bit-manipulation-extensions-under-the-jit).
The self-test reaches the new instructions with `.option arch`, which is
also the only way to reach Zalasr: GCC 15 does not take it in `-march`.

### Under Linux

`boot/rv32-emu.dts` declares all of it, with a 32-byte cache block. The
kernel boots through OpenSBI to userspace, where
`boot/initramfs/init.c` executes what a user program can reach -- 17
checks: `czero`, the hints including a prefetch of address zero,
`lw.aq`/`sw.rl`, `amocas.w`, `wrs.nto` waiting for an interrupt in
U-mode, `cbo.zero` from U-mode (which needs `menvcfg` from the firmware
*and* `senvcfg` from the kernel), and a misaligned store across a page
boundary into a page not yet mapped.

What the kernel itself executes cannot be read off a boot that
succeeded. A `-DEMU_PAIR_STATS=ON` runner counts interpreted
instructions by extension, and under `--jit` that is exact for
everything the translator declines:

| | in one boot |
|---|---|
| Zbb | 331,550 -- so the kernel's alternatives do patch its string routines in |
| `cbo.zero` | 36,225 -- its `clear_page`, 128 to a page |
| cbo.clean / flush / inval | 4,096 |
| `clmul` (Zbc) | 3,270 |
| `wrs.nto`, `wrs.sto` | 3, all of them the test program's: with one hart the kernel has nobody to wait for |

## An access is checked whole

The bus is 32 bits wide and a page is 4 KiB, so three kinds of access
are not one bus transaction: a doubleword (`fld`, `fsd`), a cache block
(`cbo.zero`), and -- with `RV32_MISALIGNED=ON`, the default -- a word or
halfword that runs across a page boundary. Each is still *one access*:
translation, PMP and the bus are asked about all of it, a part at a
time where a part is what lies in one page, and only then is any of it
carried out.

That was two defects at two widths. `fsd` was two word stores, so a
fault on the second arrived with the first already written and, under
PMP, named the upper word instead of the double. And a misaligned
access was translated once, at its first byte, then read or written as
physically contiguous bytes: across a page boundary under Sv32 it
reached into whatever frame followed, and did not fault when the next
virtual page was not mapped at all. Under Linux that is a store whose
second half lands in an unrelated page of the same process -- in the
test program, on its own counter.

A refusal in the second page reports the second page's address, because
that is the page a fault handler has to map. The address travels by
being recorded where the access is split and applied in `rv_hart_trap`,
not by an out-parameter on `rv_hart_load` and `rv_hart_store`: that was
the first version, and it cost the interpreter 1.3% of its host
instructions on CoreMark for a case most guests cannot reach. As built,
those two functions execute the same number of host instructions as
before, to the digit.

## Profiles

**RVI20U32: implemented.** It is the one ratified profile for RV32. Its
mandatory set is the base ISA -- RV32I, little-endian, with `fence.tso`
mandatory -- and this core has that and every extension the profile
lists as optional: M, A, F, D, C, Zifencei, Zicntr, Zihpm, and
misaligned loads and stores when built `RV32_MISALIGNED=ON`, which is
the default. That is a statement about the implementation, backed by
the suites in [../validation.md](../validation.md); "RISC-V Compatible"
is RISC-V International's term and is not one a test run confers.

**RVA20 and RVA22: there is no RV32 form to implement.** Both families
define 64-bit profiles only (RVA20U64/S64, RVA22U64/S64); the RVA20
text says XLEN=32 variants "would be possible" and specifies none. What
can be stated is how far this core is from the same mandatory lists
read for RV32:

| | counterpart | missing |
|---|---|---|
| RVA20U | M, A, F, D, C, Zicsr, Zicntr; Ziccif, Ziccrse, Ziccamoa and Za128rs hold by construction (one hart, a four-byte reservation) | Zicclsm -- misaligned access -- only in an `RV32_MISALIGNED=ON` build, the default; `run-arch-test.sh --misaligned` validates that build, Misalign suites included |
| RVA20S | Zifencei, Svbare, Svade, Sstvecd; Sv32 where the profile says Sv39; privileged 1.12 where it says 1.11 | Sstvala and Ssccptr are believed to hold and are neither declared nor tested as such |
| RVA22U | Zihpm, Zihintpause, Zba, Zbb, Zbs, Zicbom, Zicbop, Zicboz, Za64rs, **Zfhmin**, **Zkt** | **Zic64b** wants 64-byte cache blocks and `RV_CACHE_BLOCK_SIZE` is 32, the M7's line |
| RVA22S | Ss1p12, Sscounterenw, **Svinval** | Svpbmt is not defined for Sv32 |

So: RVA20 to within a build option and two properties nobody has
written a test for; RVA22 not, by one unprivileged extension. Of
RVA22S's options, Sscofpmf is implemented -- RVA23 makes it mandatory --
and Sstc is not.

**Zfhmin** is half precision moved and converted, never computed:
FLH, FSH, FMV.X.H, FMV.H.X and conversion to and from single and
double, in `rv_fpu.c` on SoftFloat's f16 conversions and reached by the
JIT through the FP helper. A half is boxed as a single is, one size
down -- all-ones in every bit above its sixteen -- so with D that is 48
bits, and an unboxed register reads as the canonical half NaN 0x7E00.
The architecture suite has Zfhmin and ZfhminD, and **neither holds
FCVT.D.H or FCVT.H.D**: ZfhminD is the same six instructions run with
FLEN 64. `isatest` covers the two at the boundaries -- the tie at 65520,
which overflows to nearest and only inexact toward zero, a value under
half the smallest subnormal, a signalling NaN, an unboxed register, a
reserved rm -- with expectations held to Python's binary16 rather than
to this code. Zfh, the arithmetic, is not implemented.

**Zkt** has no instructions: it promises that the integer arithmetic,
the multiplies (not divide), the rotates and logic Zbb shares with
Zbkb, and `clmul`/`clmulh` take time independent of their operand
values. For an emulator that is a property of how each one is executed,
so it was examined path by path rather than assumed. In both JIT
backends each is one host instruction or a fixed sequence -- a variable
shift masks its count with an AND, the high multiplies are SMULL/UMULL
or IMUL, MULHSU is a straight-line helper -- and in the interpreter a
C expression with no test on the values. The one exception was `clmul`:
a fixed 32 steps, but each with `if (b >> i & 1)`. GCC turned that into
CMOV on x86-64 and IT on the M7, so it never actually branched -- by
the compilers' choice. It masks each partial product with all-ones or
zero now, which is branch-free by construction. Declared to UDB, Sail,
the ISA string and the device tree; there is no suite for a timing
property.

**Svinval** is SFENCE.VMA's invalidation without its fences, so a
kernel can batch invalidations between one SFENCE.W.INVAL and one
SFENCE.INVAL.IR. One hart has nothing to order, so SINVAL.VMA is
SFENCE.VMA and the two fences are no-ops; what is real is the traps --
all three are illegal in U-mode, and mstatus.TVM stops SINVAL.VMA in
S-mode but not the fences. Both suite tests pass, on both backends.

## The JIT

`rv_ir.c` lowers RV32 to the shared IR; see
[../jit/README.md](../jit/README.md). What is specific to this frontend:

- **It translates under PMP and under Sv32.** Fetches are checked and
  walked at translation, per halfword; loads and stores go through the
  same checked accessors the interpreter uses, and the inlined RAM
  window is offered only when nothing could deny an access. Only Sdtrig
  sends everything to the interpreter.
- **What a block is for** — privilege, `satp`, whether the FP unit is
  on, the rounding mode — is its context; **what invalidates one** — a
  page-table edit, a PMP write — is a generation. Which is which was
  learned by getting it wrong in both directions:
  [../jit/staleness.md](../jit/staleness.md).
- **`SYSTEM` is declined**, deliberately, so the interpreter is the one
  place a CSR write can land. The exception is a *read* of `time`:
  Linux polls it in delay loops, and it was 99.2% of all CSR accesses
  in a boot.

### The bit-manipulation extensions under the JIT

Every instruction of Zba, Zbb, Zbc and Zbs is translated. Until this
was done they were almost all of what the JIT handed back:

| guest | interpreted under the JIT, before | after |
|---|---|---|
| CoreMark | 23,339 of 518,234 -- 98.8% B | 1 |
| Dhrystone | 120,566 of 9.4M -- 99.6% Zba | 1 |
| crypto | 65,776 of 2.7M | 1 |
| a Linux boot, 3e9 instructions | 1,308,143, of which 331,550 Zbb | 913,551, no B |

How each is lowered was chosen by asking which ones the guests execute
(`-DEMU_PAIR_STATS=ON` now lists them by instruction): the three
shifted adds, `sext.h`, `zext.h`, `andn`, `rori`, `rev8` and `bexti`,
and nothing else in measurable numbers. So:

- **open-coded**, from operations both backends lower: `sh1add`..
  `sh3add` (a shift and an add), `andn`/`orn`/`xnor`, the extensions,
  `rori`, `rev8`, `clz`/`ctz` where the host says it can, and all of
  Zbs. The IR's own `BSET`/`BCLR`/`BINV`/`BEXT` are not used: x86-64
  has them and Thumb-2 declines them, and an operation one backend
  refuses costs that host the whole block. A register bit index is a
  variable shift, which the IR masks to five bits on every consumer --
  Zbs's own rule.
- **one helper**, `rv_ir_bitop_helper`, for `clmul`/`clmulh`/`clmulr`,
  `cpop`, `orc.b`, `min`/`max`/`minu`/`maxu` and `rol`/`ror`. None of
  these is frequent here, and each would otherwise be four or five IR
  operations or a capability neither host has. A helper keeps the block
  whole, which is what matters. Its arithmetic is
  `include/rv32/rv_bitmanip.h`, shared with the interpreter.

Each is declined in a build without its extension, so the interpreter
traps on it as before. `isatest` holds all of them to an independent
model (`tests/guest/bitmanip-expect.py`) at the awkward inputs --
`clz`/`ctz` of zero, rotation and bit index 32 and 36, the sign
boundary for `min`/`max`, `clmulh` against `clmulr` -- and with every
aliasing of rd, rs1, rs2 and x0, on x86-64 and on the F746.

On the Nucleo-F746ZG it took CoreMark from 172.3 to 140.0 host cycles an
instruction at the default 32 KB cache and from 47.6 to 31.1 at 96 KB;
[../jit/tuning.md](../jit/tuning.md) has the rest of the sweep. The JIT
is still behind the interpreter at the default, which is the open
decision in [../TODO.md](../TODO.md).
